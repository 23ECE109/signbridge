The Problem

430 million people. A broken communication system.

When a Deaf person walks into a hospital, pharmacy, or emergency room, the tools available to them are inadequate — and sometimes dangerous.

🔴

Human interpreters

Expensive, unavailable on demand, impossible to schedule in emergencies. Interpreter shortages are documented in every country.

🔴

Writing / typing

Slow, dehumanizing for a real conversation, and assumes literacy in a spoken language that many Deaf people don't use as their primary language.

🔴

Existing AI sign apps

Recognize isolated gestures one at a time. Require cloud connectivity. One-size-fits-all. One-way only. No uncertainty handling. No personalization.

🔴

Google SL2T (Aug 2026)

Best-in-class — but Android/Pixel-only, sends landmarks to a server, ASL only, no two-way bridge, no personalization, no offline mode.

Three Core Innovations

What no one else does — all three together.

Each innovation exists partially in research. The combination — deployed offline on Snapdragon — has no direct prior art.

01

🎯 Uncertainty-Aware Interaction

No deployed sign-language system asks for clarification when it's unsure. SignBridge uses a three-tier confidence system that makes AI uncertainty visible and actionable — preventing silent mistranslations in medical or emergency conversations.

No prior art in deployed systems
02

👤 5-Minute Personal Enrollment

Sign language is as individual as a fingerprint. SignBridge learns your signing style with a 5-minute guided setup — deriving a 64-dim user embedding without retraining. Corrections you make are remembered across sessions.

No personalization in any deployed product
03

🔄 True Two-Way Offline Bridge

Sign → speech for the Deaf user's message. Speech → large text for the hearing partner's response. Both directions. Fully offline. No server. First system to close the full conversational loop on a PC platform.

First full two-way offline PC system

How confidence works in practice

SignBridge scores every translation and acts accordingly — never pretending to be certain.

HIGH ≥ 0.75

🔊Auto-translate & speak

Score ≥ 0.75 — translation is spoken immediately via TTS. The hearing partner hears the message.

MED 0.50–0.74

❓Disambiguation dialog

System asks: "Did you mean: (A) I have an allergy — or (B) I have a reaction?" User confirms in one tap.

LOW < 0.50

🔄Request re-sign

Confidence too low to act on. System displays: "Please sign that again." No incorrect speech is produced.

System Architecture

Every component, its purpose, and where it runs.

The entire pipeline runs inside the Snapdragon X Elite SoC. Nothing leaves the device.

1

Camera Capture & Frame Buffer CPU

30 FPS RGB frames stored in a circular 64-frame RAM buffer. Frames are never written to disk. Lighting quality check warns user if conditions are poor.

2

MediaPipe Holistic Landmark Extraction Hexagon NPU · FP16

Extracts 225 coordinates per frame: 21 landmarks × 2 hands + 33 pose landmarks. Inference: 52–76 µs/frame on Hexagon HTP. Source: Qualcomm AI Hub.

3

Temporal Encoder NPU / CPU · INT8

4-layer Transformer encoder (d=256). Input: [64, 225] normalized landmark sequence. Output: [256] sequence embedding. Pre-trained on WLASL, fine-tuned on custom 150-sign dataset.

4

Personalization Layer CPU

Fuses [256] sequence embedding with [64] user embedding via a 2-layer MLP. Derived during 5-minute enrollment. Stored AES-256 encrypted locally.

5

Context Engine CPU

Sliding window of last 5 utterances + session topic tag (Medical / Emergency / General / Work / Education). Biases decoder toward contextually appropriate vocabulary.

6

Translation Decoder + Confidence Estimator CPU / NPU

2-layer Transformer decoder. Produces top-K candidates with probabilities. Confidence score → three-tier decision. Correction memory kNN lookup for override.

7

piper-tts Speech Output CPU · ARM64

ARM64-native TTS engine. en_US-lessac-medium model (~65 MB). Speaks the final translation aloud for the hearing conversation partner. Fully offline.

8

Distil-Whisper ASR (Two-Way Mode) Hexagon NPU · FP16

Transcribes the hearing partner's speech in real time. Large text displayed on screen for the Deaf user. Source: Qualcomm AI Hub. Real-time factor < 0.1.

Why Snapdragon

Not a marketing claim. A technical requirement.

Sign-language communication is time-sensitive, spatially private, and often happens where there's no reliable network. These are exactly the conditions where cloud AI fails and Snapdragon's local NPU matters.

52 µs
Landmark extraction per frame

Hexagon HTP FP16 — 1000× within the 33ms/frame budget. Enables true real-time processing with headroom for the rest of the pipeline.

<100ms
End-to-end sign → text latency

No network round-trip. No server queue. Local inference means the system responds within the natural conversational pause.

0 bytes
Data transmitted per session

No landmarks. No video. No text. No conversation history leaves the device. Legally and practically private — essential for medical and legal use.

100%
Offline capability

Every feature works with Wi-Fi off. No subscription, no API key, no connectivity requirement. Works in hospitals, rural areas, and emergencies.

330 MB
Total core model weights

The entire AI pipeline — landmarks, encoder, decoder, ASR, TTS — fits in 330 MB. Under 600 MB RAM at runtime. No model paging required.

45 TOPS
Snapdragon X Elite NPU

Hexagon HTP delivers this throughput at a fraction of the CPU power draw — enabling continuous always-on processing without draining battery.

Honest novelty score. No single component is groundbreaking — Transformer encoders, landmark extraction, and ASR are established. The novelty is in the integration: uncertainty-as-interaction + persistent correction memory + personalization + two-way offline bridge on a Snapdragon PC. This combination does not exist as a deployed or prototyped system in the reviewed literature.

A score of 8 would require a larger dataset, a novel model architecture, or a formal user study. The 7 is defensible and buildable.
